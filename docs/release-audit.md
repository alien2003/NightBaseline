# Release audit for 0.1.0

- **Date:** 2026-11-26
- **Audited commit:** `1f5caa0` ("test(e2e): UI walk works on Android 17"), the tip of both `main` and `worktree-dev`
- **Repository:** github.com/alien2003/NightBaseline (public)

This document records the result of the pre-release audit. It contains no health data, no personal data and no
secret values. Findings that concern sensitive content describe its kind and location only.

## Scope

1. **Git history.** Every public ref (`main`, `worktree-dev`, two Dependabot branches, PR refs `refs/pull/1` and
   `refs/pull/2`): 62 commits, 354 paths, 732 blob versions, plus all commit messages. Local-only commits were
   checked too.
2. **CI.** All GitHub Actions runs (26), logs of the latest run of each workflow, and one artifact of each type
   (screenshots, debug APK, build reports, test reports).
3. **Repository settings.** Visibility, branches, branch protection, secret scanning, workflow token, Actions policy.
4. **Docs and deliverables.** README (en, ru), CHANGELOG, user guide, privacy policy, ALGORITHM, SECURITY,
   CONTRIBUTING, development guide, STATUS, ADRs, design docs, documentation index, screenshots.
5. **Release pipeline.** `release.yml`, `build-apks.yml`, `.github/scripts/*`, versionCode scheme, APK naming,
   one release dry run.
6. **Obtainium.** The import link in README.md, README.ru.md and docs/user-guide.md, the APK filter, the
   certificate hash and the badge SVG.

## Method

- History: every blob extracted with `git cat-file --batch` and searched for commit identities, the owner's private
  email, the device serial, keys and tokens (PEM blocks, JKS/PKCS12 magic bytes, GitHub/AWS/Slack/Google token
  patterns), the keystore file hash and both keystore passwords, absolute home paths, Windows profile and host names,
  date-plus-value pairs, Health Connect record IDs and JSON record dumps, Cyrillic outside the allowed paths. The
  sensitive search terms were taken from the git-ignored local files and never printed.
- Images: all 32 PNG versions opened and checked for size, status bar, metadata (tEXt, iTXt, eXIf) and content.
- CI: artifacts downloaded into the git-ignored `build/` folder and searched; logs checked for unmasked secrets,
  personal data, health-data markers and home paths.
- Settings: `gh api` (read-only).
- Docs: read against the release criteria; every relative link and anchor in tracked `.md` files resolved with a
  script.
- Release: version and changelog scripts run locally; Obtainium link decoded and its regex tested; one
  `release.yml` dry run triggered (it cannot publish, see Release pipeline).
- Nothing was changed on GitHub except the one dry-run trigger. No phone access.

## Results

### Git history: clean

- All owner commits use the noreply address as author and committer; Dependabot commits use Dependabot's noreply
  address.
- The owner's private email, real name and device serial appear in no blob and no commit message.
- No private keys, keystores, tokens or password literals. Every signing reference is an environment variable or a
  `${{ secrets.* }}` expression. No `.data/`, `.secrets/`, `local.properties`, `.env` or data-dump file was ever
  committed.
- No absolute home paths. One placeholder path (`/mnt/c/Users/<user>/...`) in
  `docs/research/pulsestages-reuse.md:71` names no user (info only).
- No health-data dumps in any text file. Fixtures state that they are generated by `SyntheticNights` with a fixed
  seed. `docs/research/metrics-matrix.md` contains only spreads, differences, coverage and counts, no personal
  absolute levels. Wireframe numbers in design docs are illustrative.
- All screenshots are JVM renders of synthetic data ("Demo watch"), without status bar or metadata, and no vendor
  assets. The Obtainium badge and launcher icons are own vector art.
- **Low:** `tools/check-language.sh` allows `res/values-ru` anywhere, so a design-time Russian copy under
  `docs/design/res/values-ru/` (no longer on `main`, still in history) passed the check.
- **Exception, see Docs:** the history check found no dumps, but the docs review found a few individual personal
  values in prose and one test (fix items 3 and 4).

### CI and artifacts: clean (no leaks), with deviations

- Artifacts contain only synthetic data; the debug APK contains no data files.
- Logs contain no secret values (all masked), personal data, health-data markers or home paths other than the
  runners' own.
- The signing key is written with restricted permissions and removed in an `always()` step; the signing job has
  read-only permissions.
- **Low:** `build-apks.yml` falls back to `--generate-notes` when CHANGELOG has no section for the tag, so release
  notes could contain generated PR text.
- **Low (hygiene):** the key-alias secret is a plain word that is also part of the temporary keystore file name, so
  log masking garbles that path and hints at the alias. The alias is not a credential.
- **Low:** comments in `ci.yml` (lines 93, 122, 192) still describe private-repository runner memory and artifact
  quota.
- **Side note:** in one CI screenshot (home, phone, light, glass, font 1.0) the sleep-duration value looks
  struck through. Possible rendering bug, unverified.

### Repository settings: issues

- Public, default branch `main`, secret scanning and push protection on, workflow token read-only, all actions
  SHA-pinned.
- **Medium:** `main` has no branch protection and no rulesets.
- **Low:** Dependabot security updates off, wiki on, any action allowed (SHA pinning not enforced).

### Release pipeline: issues (blocking)

- No release and no tags yet.
- `version-from-tag.sh v0.1.0` gives versionCode 10099, above all development builds (10001-10006); an update over
  the installed development build should work because the same key signs both.
- `changelog-section.sh 0.1.0` extracts the right section; it contains no personal or health data. The heading still
  says "unreleased".
- **Blocker:** the documented dry run cannot start (run `45860386479`, `startup_failure`). The `dry-run` caller job
  grants `contents: read`, but the nested `publish` job in `build-apks.yml` requests `contents: write`; GitHub rejects
  the whole run before any job starts. The tag-push path is not affected by this check.
- **Blocker:** CI on `main` is not green. "Build APKs" run `45860266185` failed resolving the Kotlin JVM plugin
  (likely a transient repository outage, hypothesis); the previous CI run on `main` (`45745206378`) failed with a
  Gradle configuration-cache error in `:app:prepareRobolectricDependencies` (same commit passed on `worktree-dev`).
- The last successful signed check build (`45745206352`, commit `b11e441`) verified v2 signing, the expected
  certificate digest and no network permission.

### Obtainium: clean

- The link is byte-identical in README.md, README.ru.md and docs/user-guide.md and matches what the generator in
  docs/development.md prints.
- Package id, repository URL, `includePrereleases: false`, the APK filter `^NightBaseline-[0-9.]+\.apk$` and the
  certificate hash are correct; the filter matches `NightBaseline-0.1.0.apk` and rejects `SHA256SUMS.txt` and
  pre-release names.
- Built the same way as the PulseStages link. The badge SVG is well formed with no scripts, images or fonts.
- **Low:** docs/user-guide.md lines 108-109 say `apksigner` prints the digest in colon form; it prints lowercase hex
  without colons (SECURITY.md is right).

### Docs: issues

- **Blocker (privacy, CLAUDE.md rules 5 and 11):** `docs/STATUS.md:35-37` contains exact clock times of one real
  sleep session of the owner. `docs/STATUS.md:17` contains the owner's time zone and phone model (the model also in
  three design docs; borderline, not a serial).
  `work/src/test/kotlin/io/github/alien2003/nightbaseline/work/process/DaytimeWritesTest.kt:38` uses a city-level
  time zone tied to the owner, and lines 74-75 hard-code real-looking nap times on a real date (hypothesis: copied
  from the export). The old values stay in public history (`b46fa9f`, `6d45a8d`); rewriting history is the owner's
  decision.
- CHANGELOG 0.1.0 misses the ColorOS restyle, the new launcher icon, smoother scrolling, the night-processing fix,
  the e2e suite and the system-log note.
- `docs/development.md` lacks the on-device test suite and the `check-leaks`/`check-ripple` checks, and still
  describes private-repository runners.
- `docs/STATUS.md` is stale (commit, "in progress" items, installed version, next steps).
- `docs/privacy.md` does not mention that night checks write dates and start/end times (no values) to the system log
  in every build, release included.
- `docs/README.md` and `docs/design/README.md` miss newer ADRs and docs; no ADR for the e2e suite.
- `CLAUDE.md:70` still says the repository stays private.
- README screenshots may predate `fc07ffb` (title alignment); the home alt text mentions "last 7 nights", which is not
  in the captured viewport.
- Verified OK: README (en, ru) mirror each other, disclaimer in README and app, "Vitals" never used as a feature
  name, ADRs 0001-0006 exist, all relative links resolve, CHANGELOG numbers match ALGORITHM.md.
